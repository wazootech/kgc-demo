# Verifiable Memory for Agents That Act: Provenance, Validation, and Retraction

Demo for the Knowledge Graph Conference (KGC) 2027 Call for Presentations.
Conference: May 3–7, 2027, Bryant Park, New York City. Presentation talk, 25
minutes including Q&A. Submission deadline: Friday, January 15, 2027.

This demo proves three checks, in order, with a working system:

1. **Trace** — an agent answer traced back to its source facts.
2. **Validate** — a fact checked against an agreed rule before the agent
   believes it.
3. **Retract** — revoking a fact actually removes it from future use, and every
   answer that used it can be found.

The scenario is fictional support data about a fictional company, Fable Systems.
It names no real customer, partner, or deployment.

## Run it

Requires Deno 2.x. No hosted service, no login, no API key. The first run
downloads the pinned dependencies from JSR, so it needs network once; after that
it runs offline from the Deno cache. Under 5 minutes, start to finish.

```sh
deno task demo   # human-readable run
deno task eval   # re-run and rewrite eval/results.md with measured numbers
deno task test   # automated tests of the same five steps
```

## What the demo does

A support agent answers two compatibility questions from a small World
(`world/seed.ttl`, 28 quads). Each compatibility claim is a node carrying
`dct:source`, `ex:validUntil`, and `ex:testReference`, so the answer query
returns the source with the answer.

- **A1:** "Can the Aurora Laptop use the Beacon 27 Monitor at 144 Hz?" Answered
  from claim C1, sourced to lab test `LAB-2026-10-14-07`.
- **A2:** "Can the Beacon 27 Monitor use the Halo Dock?" Answered from claim C3,
  sourced to the Halo Dock vendor specification.

Then a candidate claim C2 — Aurora Laptop works with Halo Dock, sourced to a
forum post, with no validity date — is checked in a scratch World and
**rejected**: it breaks V1 (untrusted source) and V2 (no validUntil), and is
never imported into the real World.

Then claim C1 is revoked with SPARQL `DELETE DATA` (vendor withdrew the 144 Hz
claim). Both questions are asked again: A1 changes to "No verified compatibility
on record", A2 is unchanged. The answer log (`eval/answers.jsonl`) shows A1 was
the one earlier answer that used C1.

## Measured results

See `eval/results.md`, generated by `deno task eval`. Headline numbers from the
run recorded there: 28 quads imported, 15 SPARQL queries, 2 of 2 answers traced
to a source, seed validation 4 of 4 checks passed, candidate C2 rejected with 2
violations, 7 quads deleted on retraction, 1 of 2 answers changed on re-ask.
Tests: 5 passed, 0 failed (`deno task test`).

## Files

- `world/seed.ttl` — the World: 28 quads, fictional Fable Systems data.
- `world/retractions.jsonl` — the revocation record, written by the demo.
- `shapes/validation.ttl` — the SHACL shape: the agreed rule, as a specification
  (see "What it does not do yet").
- `src/scenario.ts` — the five steps, against the real Worlds stack.
- `src/validate.ts` — checks V1–V4 as SPARQL ASK queries.
- `src/demo.ts` — the human-readable runner.
- `src/records.ts` — writes the answer log and retraction record.
- `eval/run.ts` — re-runs the scenario and writes `eval/results.md`.
- `eval/results.md` — measured numbers from the last eval run.
- `eval/answers.jsonl` — every answer, before and after retraction.
- `test/scenario.test.ts` — 5 automated tests of the same five steps.

## Built on

- [`@worlds/sdk@0.9.0`](https://github.com/wazootech/worlds-sdk-ts)
  (`createMemoryWorldsSdk` — in-memory Worlds SDK: quad store + search
  - SPARQL over one shared store), MIT.
- [`@wazoo/sparql-engine@0.4.4`](https://github.com/wazootech/sparql-engine)
  (SPARQL 1.1 & 1.2 query and update engine), MIT.
- [`@wazoo/reasoner@0.4.0`](https://github.com/wazootech/reasoner) was checked
  for validation support and does not provide it (OWL 2 RL materialization
  only). It is not a dependency of this demo.

## What it does not do yet

- **There is no SHACL engine in this stack.** No SHACL validator ships in
  `@worlds/sdk` 0.9.0, `@wazoo/sparql-engine` 0.4.4, or `@wazoo/reasoner` 0.4.0
  (checked by searching all three public repos, 2026-11-06).
  `shapes/validation.ttl` is the agreed rule written in SHACL so a reviewer can
  read it. The checks actually executed are the SPARQL ASK translations of V1–V4
  in `src/validate.ts`, run by the real SPARQL engine. A real SHACL engine would
  additionally catch `sh:closed` violations and enforce datatypes per property;
  this translation cannot express those.
- **A deleted fact is gone.** `DELETE DATA` removes the 7 quads of claim C1 from
  the World, and they are not recoverable from the World. There is no tombstone
  in the World itself. The retraction record (`world/retractions.jsonl`) and the
  answer log (`eval/answers.jsonl`) are files written by this demo, outside the
  World — not Worlds features.
- **The answer log only covers this demo.** An answer given by another agent, or
  in another session, is not in this log and would not be found by it. Finding
  every answer that used a revoked fact, in general, needs an answer log kept by
  the agent system, not just by this demo.
- **Validation is checked at import time, in a scratch World, not enforced by
  the store.** Nothing in the World stops a client from writing an unchecked
  quad directly. The gate exists in this demo's flow, not in the SDK.
- **One scenario, one evaluation date.** Validation uses a fixed evaluation date
  of 2026-11-06. The scenario wall time (~70 ms) is a single run on one machine,
  not a benchmark.
